# Audio ABI checkpoint

Date: 2026-08-26

This checkpoint separates verified resource loading and gameplay-side audio
calls from unverified host sound output. It does not claim that audio is
playable yet.

## Regression gate

The full decrypted corpus still reaches the normal watchdog exit for all 20
bundles after the clickwheel and Tetris rendering changes. The latest report
and per-title logs are:

```text
/tmp/fliwheel_regression_20260826_auto/20260825_221028_decrypted_games.md
/tmp/fliwheel_regression_20260826_auto/20260825_221028_logs/
```

No panic, fatal exception, unmapped access, or memory-fault signature appeared
in that sweep. The report remains a startup/rendering smoke test, not a
gameplay or sound test.

## Measured resource path

With `CLICKY_AUDIO_TRACE=1`, Tetris resolves its guest filename pointers back
to the bundle assets. The pointer is one byte before the C string in this
callsite, so the tracer recognizes the offset and logs the host path. The
focused frame-correlated artifact is:

```text
/tmp/fliwheel_tetris_gameplay_audio_trace_20260826_b.log
```

The parsed startup path registers these real assets:

```text
Drop.wav Move.wav MoveFail.wav Hold.wav Clear.wav Tetris.wav
Level.wav GameOver.wav Lock.wav Menu.wav
```

The trace also confirms that the shared runtime sees the same startup family
across titles. The observed Tetris ordinals are:

```text
0, 1, 7, 8, 9, 10, 11, 12, 17, 18, 23, 40, 43, 48, 51, 52, 53, 55, 56
```

The current `AsyncFileIO` path stages WAV headers and offset-based payload
reads. The WAV bytes do not arrive as direct `Audio` arguments; the remaining
binding is through the runtime's audio buffer/source objects.

## Gameplay reachability

The input-scripted Tetris run now reaches the board and produces repeated
gameplay-side calls. In the focused trace, the left, right, and down events
are visible at frames 300, 330, and 400; each is followed by:

```text
Audio:13, Audio:14, Audio:15, Audio:2
```

Those calls use `r0=0xffffffff`, `r1/r2=0x7800`, and the shared table pointer
`r3=0x18025ec8`. They do not carry a direct WAV pointer or a resolved sound
slot. Startup separately registers all ten WAV resources through `Audio:0`
and allocates/configures the shared audio state, but the resource-to-buffer
handle relationship is still unresolved.

The gameplay control evidence is recorded in
`docs/game_tests/20260826_tetris_gameplay_controls.md`.

## Stream-manager and channel evidence

The return-path probe is:

```text
/tmp/fliwheel_tetris_audio_stream_manager_trace_20260826_b.log
```

It shows the audio-stream manager accepting the sampled WAV requests: the
initiator returns `r0=1` at `0x1801d840`, and the manager returns slot `r6=0`
at `0x1801d858`. The secondary-owner path at `0x1801d824` also reports valid
byte counts and a selected slot. There is no observed `-1` return from this
manager in the sampled startup sequence, so the resource-table `-1` values are
not evidence of a failed WAV read.

The adjacent channel-status watch is:

```text
/tmp/fliwheel_tetris_audio_channel_watch_20260826.log
```

The guest zeroes the channel-status area at `0x1802400c` and sets the type-1
channel active at `0x18005914`. Separately, the resource table at
`0x18025ec8` is populated by the `Audio:0` callsite and later reset to `-1`
by the guest release path after `Audio:1`. Gameplay then reaches
`Audio:13/14/15/2` with those released entries. This identifies the remaining
boundary as the lifetime/meaning of the Audio object handles and their source
buffers, rather than the asynchronous file path.

## Open boundary

Tetris now provides a verified gameplay-side transition, but the HLE still
has no evidence-backed host playback sink. The current trace proves that the
guest reaches its audio calls and that the WAV bytes are staged; it does not
yet prove which staged PCM range should be submitted for each call.

The next audio gate is to correlate the `Audio:0` return value and subsequent
`Audio:1` release with the `Audio:13/14/15/2` consumer, determine whether the
table is intentionally temporary or missing a persistent source handle, and
only then map the selected handle to staged PCM before adding a host sink and
waveform regression.

The local firmware images were inspected as supporting material, but their
packed `Firmware.MSE` strings alone do not establish this game-framework ABI;
they are not used as a substitute for a measured guest call trace.
